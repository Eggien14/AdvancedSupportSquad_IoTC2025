## ⚙️ Initial Configuration

### IPv4 Configuration (.env file)
**CRITICAL**: Configure your network IP address in `.env` file:

```bash
# Edit ASS_server\.env
SERVER_IP=192.168.1.100  # Replace with your actual IP

# Other important settings:
MYSQL_ROOT_PASSWORD=123456789
MYSQL_DATABASE=iotc25_advanced_support_squad
MYSQL_USER=eggien
MYSQL_PASSWORD=0363802865
API_PORT=8136
CACHE_ENABLED=true
```

**IPv4 Setup Instructions:**
1. Find your IP: `ipconfig` (Windows) or `ip addr` (Linux)
2. Edit `.env` file with your IP address
3. Restart services after IP change: `docker-compose down && docker-compose up -d`
4. SSL certificates auto-regenerate with new IP

## 🚀 Method 1: PowerShell Script (docker.ps1) - RECOMMENDED

**Best for**: Production-like development and quick deployment

### Available Commands:
```powershell
# Start full version (nginx + SSL + HTTPS)
.\docker.ps1 full

# Start simple version (HTTP only, faster startup)
.\docker.ps1 simple

# Stop all services
.\docker.ps1 down

# Restart current configuration
.\docker.ps1 restart

# View nginx proxy logs
.\docker.ps1 logs

# Check container status
.\docker.ps1 status

# Show help
.\docker.ps1
```

### Full Version vs Simple Version:

#### Full Version (.\docker.ps1 full)
- **Features**: Nginx proxy, SSL/TLS, HTTPS support, production-ready
- **Ports**: HTTP (8136), HTTPS (8118), Detection (8100), DB (3308)
- **Use when**: Production deployment, testing SSL, external access needed
- **Startup time**: ~60-90 seconds (SSL certificate generation)
- **Memory usage**: ~2-3GB RAM
- **URL**: https://localhost:8118/docs (HTTPS) or http://localhost:8136/docs

#### Simple Version (.\docker.ps1 simple)
- **Features**: Direct API access, HTTP only, faster development
- **Ports**: HTTP (8136), Detection (8100), DB (3308)
- **Use when**: Local development, testing, debugging
- **Startup time**: ~30-45 seconds
- **Memory usage**: ~1.5-2GB RAM
- **URL**: http://localhost:8136/docs

### Step-by-Step Execution:
```powershell
# Navigate to project directory
cd "C:\Users\Admin\Project\IoTc25\project\Server\ASS_server"

# For development
.\docker.ps1 simple
# Wait for "SIMPLE Services started!" message
# Open: http://localhost:8136/docs

# For production testing
.\docker.ps1 down        # Stop simple version first
.\docker.ps1 full
# Wait for "FULL Services started!" message
# Open: https://localhost:8118/docs (HTTPS)
# Or:   http://localhost:8136/docs (HTTP)
```

## 🐳 Method 2: Docker Command Line - Manual Control

**Best for**: Understanding Docker internals, debugging, custom configurations

### Simple Version (HTTP only):
```bash
# Start simple version
docker-compose -f docker-compose.simple.yaml up -d --remove-orphans

# View logs
docker-compose -f docker-compose.simple.yaml logs -f

# Stop
docker-compose -f docker-compose.simple.yaml down --remove-orphans

# Rebuild and start
docker-compose -f docker-compose.simple.yaml up -d --build --remove-orphans
```

### Full Version (Nginx + SSL):
```bash
# Start full version
docker-compose up -d --remove-orphans

# View logs
docker-compose logs -f

# View specific service logs
docker-compose logs -f api
docker-compose logs -f detector
docker-compose logs -f nginx-proxy
docker-compose logs -f db

# Stop
docker-compose down --remove-orphans

# Complete rebuild
docker-compose down --remove-orphans
docker-compose build --no-cache
docker-compose up -d --remove-orphans
```

### Advanced Docker Commands:
```bash
# Scale detector service (multiple instances)
docker-compose up -d --scale detector=2

# Build specific service
docker-compose build api
docker-compose build detector

# Force recreate containers
docker-compose up -d --force-recreate

# Remove everything including volumes
docker-compose down -v --remove-orphans
docker system prune -a --volumes

# Check container health
docker-compose ps
docker inspect <container_name>
```

## 🐍 Method 5: Virtual Environment (my_env) - Local Development

**Best for**: Pure Python development, library testing, debugging without Docker overhead

### Prerequisites:
- Python 3.11+
- MySQL 8.0 server running locally
- All system dependencies installed manually

### Setup Virtual Environment:
```bash
# Create virtual environment
python -m venv my_env

# Activate virtual environment
# Windows:
my_env\Scripts\activate
# Linux/Mac:
source my_env/bin/activate

# Upgrade pip
python -m pip install --upgrade pip

# Install dependencies
pip install -r lib_requirement.txt

# Special PyTorch CPU-only installation
pip uninstall torch torchvision -y
pip install --index-url https://download.pytorch.org/whl/cpu torch torchvision

# Verify PyTorch CPU-only
python -c "import torch; print('CUDA available:', torch.cuda.is_available())"
# Should output: CUDA available: False
```

### Database Setup (Local MySQL):
```sql
-- Connect to MySQL as root
mysql -u root -p

-- Create database and user
CREATE DATABASE iotc25_advanced_support_squad;
CREATE USER 'eggien'@'localhost' IDENTIFIED BY '0363802865';
GRANT ALL PRIVILEGES ON iotc25_advanced_support_squad.* TO 'eggien'@'localhost';
FLUSH PRIVILEGES;

-- Import schema
mysql -u eggien -p0363802865 iotc25_advanced_support_squad < db/db_init/001_schema.sql

-- Import sample data
mysql -u eggien -p0363802865 iotc25_advanced_support_squad < db/db_insert/002_insert_product_master.sql
mysql -u eggien -p0363802865 iotc25_advanced_support_squad < db/db_insert/003_insert_cart_items.sql
# ... continue with other insert files
```

### Running Services Manually:

#### Start API Service:

#### Start Detector Service:

## 🌐 Method 6: Production Deployment

**Best for**: Live production servers, cloud deployment, enterprise environments

### Production Environment Setup:

#### Server Requirements:
- **OS**: Ubuntu 20.04+ or CentOS 8+ or Windows Server 2019+
- **CPU**: 4+ cores (8+ recommended)
- **RAM**: 8GB+ (16GB+ recommended)
- **Storage**: 50GB+ SSD
- **Network**: Static IP address, ports 80/443/8136/8118 accessible

#### Production Configuration:

1. **Update .env for Production**:
```bash
# Production .env
SERVER_IP=your.production.ip.address
MYSQL_ROOT_PASSWORD=very_secure_root_password
MYSQL_DATABASE=iotc25_production
MYSQL_USER=production_user
MYSQL_PASSWORD=very_secure_user_password
API_PORT=8136
CACHE_ENABLED=true
```

2. **SSL Certificate Configuration**:
```bash
# Option 1: Auto-generated certificates (development/testing)
# Certificates auto-generate with IP from .env

# Option 2: Custom SSL certificates (production)
# Place certificates in nginx/certs/
cp your-domain.crt nginx/certs/cert.pem
cp your-domain.key nginx/certs/key.pem
```

3. **Production Docker Compose**:
```yaml
# docker-compose.prod.yaml
version: '3.8'
services:
  api:
    deploy:
      replicas: 3
      resources:
        limits:
          cpus: '1.0'
          memory: 1G
    restart: always
    
  detector:
    deploy:
      replicas: 2
      resources:
        limits:
          cpus: '2.0'
          memory: 2G
    restart: always
```

### Production Deployment Steps:

#### Cloud Deployment (AWS/Azure/GCP):
```bash
# 1. Clone repository on production server
git clone <repository-url>
cd ASS_server

# 2. Configure environment
vim .env  # Update with production values

# 3. Deploy with production compose
docker-compose -f docker-compose.prod.yaml up -d

# 4. Setup reverse proxy (if needed)
# Configure your cloud load balancer to point to ports 8136/8118

# 5. Setup monitoring
docker-compose logs -f
```

#### On-Premises Deployment:
```bash
# 1. Ensure Docker is installed on production server
curl -fsSL https://get.docker.com -o get-docker.sh
sh get-docker.sh

# 2. Install Docker Compose
curl -L "https://github.com/docker/compose/releases/latest/download/docker-compose-$(uname -s)-$(uname -m)" -o /usr/local/bin/docker-compose
chmod +x /usr/local/bin/docker-compose

# 3. Deploy application
git clone <repository-url>
cd ASS_server
docker-compose up -d

# 4. Setup systemd service (Linux)
sudo vim /etc/systemd/system/shopping-cart.service
sudo systemctl enable shopping-cart.service
sudo systemctl start shopping-cart.service
```

### Production Monitoring:

## 🔍 Troubleshooting Guide

### Common Issues and Solutions:

#### Port Conflicts:
```bash
# Problem: Port already in use
# Solution: Check and kill processes
netstat -ano | findstr ":8136"
taskkill /PID <process_id> /F  # Windows
kill -9 <process_id>           # Linux

# Or use different ports in .env
```

#### Docker Issues:
```bash
# Problem: Docker containers won't start
# Solution: Clean Docker environment
docker-compose down -v --remove-orphans
docker system prune -a --volumes
docker network prune
.\docker.ps1 simple  # Restart
```

#### SSL Certificate Issues:
```bash
# Problem: HTTPS not working
# Solution: Regenerate certificates
docker-compose restart nginx-proxy

# Check certificate details
docker exec ass_server-nginx-proxy-1 \
  openssl x509 -in /etc/nginx/certs/cert.pem -text -noout
```

#### Database Connection Issues:
```bash
# Problem: Can't connect to database
# Solution: Check database health
docker exec ass_server-db-1 mysqladmin ping -u eggien -p0363802865

# Reset database
docker-compose down -v
docker-compose up -d db
# Wait for database to be ready, then start other services
```

#### Performance Issues:
```bash
# Problem: Slow response times
# Solution: Check resource usage
docker stats

# Scale services
docker-compose up -d --scale api=2 --scale detector=2

# Enable caching
# Edit .env: CACHE_ENABLED=true
```

#### Network Issues:
```bash
# Problem: Services can't communicate
# Solution: Check Docker networks
docker network ls
docker network inspect ass_server_default

# Restart networking
docker-compose down
docker-compose up -d
```
